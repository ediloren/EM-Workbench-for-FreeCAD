Creating a 3D FasterCap / FastCap input model

FC tools convert FreeCAD geometry into a frozen panel model that you inspect before export.

Prepare the model and solver

  1. Create a document and make the required solids or surfaces, for example a metal sphere inside a dielectric box. Use one consistent geometry scale. Decide which small gaps, films, holes and contacts are intentional; these can strongly affect capacitance.
  2. Switch to the E.M. workbench. An FCSolver is created automatically when you create the first FC object if none exists; you can also create it with FasterCap / FastCap Solver. Use only one per document. On its Data tab select 3D, the TargetSolver, geometry Units, and the background relative SpacePermittivity. Set the export Folder and Filename; the list filename receives .lst when necessary. FCSolver is a settings object, not a visible shape.

Define conductors

  1. Select a solid, shell, surface, or faces and click FCConductor. Use one FCConductor for each electrical potential. It may contain touching, overlapping, or disconnected Base objects; the panelizer forms their exposed boundary.
  2. To extend a conductor, select that FCConductor together with more geometry and click FCConductor again. Set DefaultPermittivity to the surrounding relative permittivity used where no dielectric interface provides a more specific value.

Define dielectric regions and interfaces

  1. Select the boundary faces or a dielectric solid and click FCDielectric. A selected solid contributes its boundary; selected open faces define only those interfaces. Extend an existing dielectric by selecting it with additional geometry and clicking the command again.
  2. Set InnerPermittivity and OuterPermittivity. Select the FCDielectric to see arrows: the arrow side is Outer and the opposite side is Inner. Solid boundaries are oriented outward, leaving the solid material on the Inner side. For open interfaces, use Orientation: Reversed if the source normals point the wrong way. Arrows appear only while selected, both before and after panelization; tessellated surfaces use a distributed sample of arrows.

How conductors and dielectrics may be arranged

An FC object assigns electrical meaning to its Base geometry. Use these rules when deciding whether CAD bodies belong to one object or several:

  • Parts of one conductor: touching or overlapping solids at the same potential should belong to the same FCConductor. They are combined transiently into one exposed boundary. Disconnected pieces may also share an FCConductor when they are intentionally at the same potential.
  • Different conductors: conductors at different potentials may be separated by background space or dielectric, and one may sit inside a cavity or enclosure formed by another. They must not occupy the same volume or share surface area. A physical edge or point contact would be a short circuit, so either combine the pieces into one FCConductor or introduce the intended gap or dielectric separation.
  • Conductors embedded in dielectrics: a solid conductor may be partly or wholly inside a dielectric solid; the CAD volumes may overlap because the conductor replaces the dielectric material it occupies. No preliminary Boolean cut is required. The conductor surface is split where it crosses a dielectric boundary, and each portion receives the permittivity of the material immediately outside it. Dielectric boundary portions inside the conductor are removed from the analysis geometry, not from the original CAD object.
  • Conductor–dielectric contact: a solid conductor may touch or have a coincident face with a dielectric boundary. The conductor panel replaces the coincident dielectric panel so solver panels do not overlap. A zero-thickness conductor surface is different: it may lie inside one uniform material, but it cannot coincide with a dielectric discontinuity because the required FastCap B element is not supported.
  • Nested dielectrics: one dielectric solid may be fully embedded in another. At a point contained by several nested volumes, the smallest enclosing region supplies the local permittivity. Give every boundary the correct Inner/Outer values and inspect its arrows.
  • Touching or overlapping dielectrics: touching or intersecting solids in the same FCDielectric are allowed and combined transiently. Equivalent coincident interfaces are merged. Distinct regions with incompatible coincident interfaces or partially overlapping volumes of different permittivities are ambiguous and diagnosed. Prefer nested volumes, clean shared boundaries, or Boolean-partitioned regions.
  • Open interfaces: an FCDielectric made from open faces describes only those interfaces; unlike a dielectric solid, it does not classify an enclosing volume away from the faces. Use it for a known material boundary, set both side permittivities explicitly, and avoid defining the same interface twice. Exact intersections and T-junctions are split into aligned seams, but GeometryTolerance does not close real gaps.

Optional defeaturing: decide what may be approximated

Defeaturing is off by default. It changes only temporary analysis shapes, never the Base objects, their placements, or their parametric history. Boundary extraction, solid classification, material splitting and meshing all use the same prepared geometry. The exported model is therefore an approximation when these controls are enabled.

  1. On FCSolver, enable DefeaturingEnabled. Start with the default DefeaturingRelativeSize = 0.002 and DefeaturingRelativeDeviation = 0.002 only if a 0.2% component-scale approximation is acceptable for your model.
  2. Relative Size identifies small-feature/contact candidates. Its reference length is the original bounding-box diagonal of each source solid or explicit shell/face, recursively separating compound children; it is not the entire document size. For a 10 mm cube, 0.002 corresponds to about 0.0346 mm. A small disconnected component does not inherit the size of a distant large body. Relative Size and Relative Deviation are local decimal-text fields: their entered precision is displayed without changing FreeCAD's global Units/Decimals preference.
  3. Relative Deviation limits cumulative boundary movement using the same reference length. Translation and uniform contraction have geometric bounds. OCC small-face removal and local interface reconstruction use bidirectional sampled boundary-distance audits plus validity and volume checks; reconstruction also checks the selected analytic support's mismatch. The sampled audit is approximate, not a mathematical certificate. Each accepted operation consumes the remaining movement budget. Zero deviation prevents geometry edits.
  4. Choose DefeaturingPolicy. Align contacts permits small solid-feature removal, safe translation of parallel planar contacts, and local BREP reconstruction of nearby planar (including slightly tilted), cylindrical and spherical interfaces. Align and regularize also permits bounded contraction of a whole connected curved solid to open tangent or near-tangent contacts. Contraction can change an isolated tangency into a clearance and changes the whole solid slightly; inspect whether that is physically acceptable.
  5. On each FCConductor or FCDielectric, choose Defeaturing: Inherit, Disabled, or Custom. Inherit uses the solver controls; Disabled fixes that object's geometry; Custom uses its own size, deviation and policy even when the solver default is off. Object numeric controls are read-only unless Custom is selected.
  6. DefeaturingPriority selects the reference for alignment: higher priority stays fixed relative to lower priority. Disabled objects are always fixed; ties favour components with existing positive-area interfaces, then conductors and document order. For local repairs at equal priority, the other enabled participant may be repaired if that preserves existing contacts. An enabled neighbour may still change relative to a disabled object. Disable defeaturing on all participants when an intentional gap/contact must be preserved exactly. Priority does not prohibit curved-solid contraction; use Disabled or Align contacts for that.

The hybrid repair operates on copied, trimmed BREP faces, including faces of imported or Boolean-generated shapes; it does not edit primitive dimensions or require parametric history. Native offset collars and Boolean splits replace a selected analytic support and retrim adjacent faces. A local fuzzy General Fuse is a fallback, particularly for open faces, but increased kernel tolerance alone does not count as a repair: the resulting edges must agree with their supporting surfaces. A selected face may change over its full extent, not just the overlap footprint. Relative Size gates the complete face-support mismatch; it is not applied as a document-wide Boolean tolerance.

The workbench reports accepted alignments, local repairs, feature removals and curved-contact regularization as warnings for review. Existing positive-area contact footprints must survive; it will not automatically short distinct FCConductors or introduce new overlap of incompatible dielectric materials. Ambiguous alignments, unsupported features, failed kernel operations and exceeded movement budgets leave the affected candidate unchanged and produce warnings where detected. Small patches remaining after material splitting are also reported; none are simply discarded from the mesh. Collapsing a thin coating can change which conductor faces border dielectric: review the prepared geometry and permittivity display, not only the panel count.

This is a bounded heuristic, not universal CAD healing. Local support reconstruction currently recognizes planes, cylinders and spheres; it cannot infer electrical intent, repair arbitrary splines, cones, complex trims or non-convex cases, or automatically reconcile every open-surface contact. Failed fuzzy/reconstruction attempts are retained for manual repair rather than accepted as high-tolerance geometry. Some ambiguous or narrow features can remain. Inspect the preview and diagnostics, and repair the CAD model manually where necessary.

For the supplied offset-cube example, alignment removes the 0.001 mm strip. For the sphere/box example, the original intersection contains exact tangent cusps: merely refining the mesh cannot eliminate their acute angles. Regularization opens a small clearance. Compare with the original CAD and vary the controls to assess whether the resulting capacitance model is acceptable.

To retain a genuine small feature, use Disabled or smaller custom thresholds. Curved meshing remains controlled separately by PanelCurvatureTolerance. A narrow but well-shaped region can require many panels; an exact acute corner or tangent cusp may make triangles above 15 degrees impossible without changing the geometry. Smaller curvature tolerance is not a cure for such corners. Bad-triangle checks remain active and export is blocked by errors.

GeometryTolerance remains a numerical comparison/classification tolerance. Do not increase it to request defeaturing or to conceal real gaps. Defeaturing uses local candidate filtering and bounded passes, but kernel operations and subsequent meshing can still be expensive. Removing tiny strips often reduces panel count greatly; opening a curved clearance can still require a dense mesh.

Create and inspect the panelization

  1. Before panelization, each FC object displays its live Base geometry beneath it in the tree. Toggling the FC object's visibility shows or hides all its Bases. Click Create FC Panelization to process all FC objects, including optional defeaturing. Bases are then hidden and FC objects show the frozen tessellation. You can independently show a Base again to compare the approximation.
  2. Read the Report view diagnostics and inspect seams, curves, contacts, material boundaries and red panels. Correct every error and review approximation warnings. Valid panels use the FC object's Shape Appearance and transparency; only individually identified problematic panels use Bad Panel Color. Non-manifold junctions are not automatically warnings, since legitimate material interfaces can meet there.
  3. Adjust PanelCurvatureTolerance for curved surfaces; it is an approximate relative deviation, sagitta divided by local minimum principal radius. The Netgen segment setting follows approximately N = 1 / sqrt(8 × tolerance). Smaller values usually increase panel count. For FastCap, MaxPanelSize also limits panel edges. Connected surfaces are meshed together to retain shared seams, not independently face by face.
  4. The progress dialog shows the current phase. Cancel is checked between processing steps and periodically during panel creation, grouping, and validation; an ongoing OCC or Netgen call must still return before cancellation can take effect. The final Report message includes generated panel count, errors, warnings and total elapsed seconds, including geometry preparation, meshing, validation and preview publication. Cancellation/failure also reports elapsed time.
  5. Panelize again after geometry, Base, material, curvature or defeaturing changes. Edits do not update the frozen preview. FC visibility now controls the panelization and its associated display aids; Base visibility remains independently available. Save the CAD document to retain the model and settings. Panels are transient: after reopening, panelize again.

Export

  1. When the preview has no errors and its warnings are understood, click Export FasterCap / FastCap. Confirm overwrite if files already exist. The selected folder receives the .lst file and its referenced geometry files. FasterCap output includes FC-object appearance colors and transparency, converted to the output format's alpha convention.
  2. Export always writes the last panelization you inspected. If the model changed afterward, the command warns and still exports that frozen snapshot; panelize again first when the changes must be included.

Validation examples

The repository's Test folder contains the two original defeaturing examples and additional source models for rotated contacts, protected conductor gaps, cylinder tangency, and a small fillet with a disconnected miniature body. Open a model, inspect its solver/object settings, and run Create FC Panelization. For the two original files, enable solver defeaturing first; they have deliberately not been overwritten. The test runner writes .validation.json results, with separate failure logs when an assertion fails.
