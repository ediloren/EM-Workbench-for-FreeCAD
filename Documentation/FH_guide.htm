Creating and inspecting FastHenry models

The FH tools prepare conductor models for FastHenry resistance and inductance extraction. Commands are available in the E.M. FastHenry tools toolbar and the EM menu. There are two workflows:

Starting pointWorkflow
New model built in FreeCADCreate native FH nodes, segments, paths, uniform planes and ports; configure FHSolver; then export with FHInputFile. Edit the model through its FreeCAD properties and linked base geometry.
Existing FastHenry input fileUse Import FastHenry file to visualize its geometry, including nonuniform planes. Edit the source and referenced plane-discretization files in the highlighted text editors, then use Save & Reload. The import creates visualization geometry rather than native FH solver primitives.

For the native workflow, follow sections 1–8. For importing and editing existing files, see section 9. Section 10 covers the Python API. FastHenry is a separate solver installation; neither exporting nor importing geometry starts a simulation.

1. Prepare the geometry and choose a scale

FastHenry represents conductors as straight segments of rectangular cross-section connected at nodes. Build the intended current and return paths explicitly. A CAD solid alone is not automatically converted into an FH conductor: use FHSegment for a straight centreline, FHPath for a connected sequence of edges, and FHPlane for a uniform rectangular reference plane.

  • Use positive segment widths, heights and plane thicknesses, and distinct endpoints for every segment.
  • Keep gaps and junctions intentional. Touching or overlapping displayed shapes do not establish electrical connections; connections follow node references and FHEquiv relationships.
  • Use one native FHSolver per document. Keep unrelated native FH models in separate documents: FHInputFile exports the supported FH objects throughout the document, regardless of selection or visibility.
  • Give exported objects distinct, simple Labels without whitespace. Labels are used to construct node, segment and plane names in the input file.

Native FH dimensions are exported as numerical values in FHSolver.Units. For ordinary FreeCAD millimetre geometry, keep Units = mm. A numerical length of 10 with Units = mm represents 10 mm; the same coordinates with Units = um represent 10 micrometres. Changing Units does not resize the CAD geometry or automatically rescale existing conductivity values. An explicitly entered FreeCAD quantity is first converted to its internal numerical length before export.

FHImport uses a different scale convention: it reads the file's units and converts the displayed geometry to physical FreeCAD millimetres. No FHSolver is needed for that import.

2. Configure FHSolver

Create an FHSolver in the active document and inspect its Data properties before exporting. If several exist, FHInputFile uses the first one it finds.

PropertyUser choice
UnitsFastHenry length unit: km, m, cm, mm, um, in or mils. The default is mm. This controls the physical interpretation of exported numerical dimensions.
SigmaDefault conductivity in 1/(Ohm × selected length unit). Newly created solvers use copper, scaled for the selected unit at creation: 5.8e7 for m, 5.8e4 for mm, or 58 for um. Recheck Sigma after changing Units.
nhinc / nwincDefault number of parallel filaments through segment height and width. Both default to 1. Use positive integers. Increase these to resolve skin and proximity effects.
rh / rwDefault grading ratios for filament sizes through height and width. Both default to 2; 1 gives equal subdivision. The native workbench properties are integers, although FastHenry input files can contain real-valued ratios.
fmin / fmaxMinimum and maximum frequencies in Hz. Defaults are 1 and 1e9. For a logarithmic sweep use positive frequencies and fmax at least fmin. For a single nonzero frequency set both to that value. In the bundled solver, fmin = 0 requests the DC case only.
ndecDesired logarithmic frequency steps per decade; default 1. Use a positive value. Successive frequencies differ by 10^(1/ndec), so fmax is not necessarily a sampled point.
Folder / FilenameExport destination. Defaults are the user's home folder and fasthenry_input_file.inp. Include the desired extension in Filename.

To convert a conductivity from S/m, multiply it by the number of metres per selected length unit. For example, copper at 5.8e7 S/m becomes 5.8e7 × 0.001 = 5.8e4 for .units mm. Native Sigma properties are plain numeric values, not automatically converted material quantities.

3. Create FHNodes and FHSegments

  1. Use FHNode to place a node interactively. Alternatively, select Draft Point objects and create FHNodes from their positions.
  2. Inspect each node's X, Y, Z and Placement. Those coordinates determine its exported position.
  3. Select two FHNodes and click FHSegment. Check NodeStart and NodeEnd.
  4. Alternatively, select a Draft Line and create an FHSegment from it. The command creates endpoint FHNodes and links the line as Base. With no suitable selection, FHSegment prompts for two points and creates the nodes and segment.
  5. Set Width and Height; their defaults are 0.2 in numerical CAD length units. Use the segment's positive Sigma, nhinc, nwinc, rh and rw values to override the solver defaults. Zero values for these override properties are omitted from the export, allowing the defaults to apply.

ww specifies the cross-section width direction. Leave it zero for the FastHenry default: width lies in the global XY plane perpendicular to the segment, with the X direction used for a vertical segment. For an explicit orientation, supply a nonzero direction perpendicular to the centreline and inspect the result. Endpoint order defines a reference direction; it does not prescribe the solved current.

A segment based on a line follows the Base endpoints. Editing its FHNodes independently can be undone by the next recompute because the Base remains authoritative. For a segment created directly between FHNodes, edit those nodes to move its endpoints.

4. Create FHPaths from connected edges

Select a sketch, Draft wire, or other supported shape containing edges, then click FHPath. The tool sorts the edges, creates FHNodes and displays a series of rectangular segments. Its Nodes list exposes the generated nodes for electrical connections. The exporter writes ordinary node and segment statements for the path.

Set Width, Height, Sigma, ww and the filament parameters as for FHSegment. A path uses one set of those properties for all its segments. Use separate paths or segments when cross-sections or materials change.

Discr controls subdivision of curved edges; the default is 3. Straight line edges are not subdivided by this setting, and small circular or elliptical edges can remain single chords relative to the cross-section size. Inspect the actual displayed approximation rather than assuming every curve receives exactly Discr segments. Recompute after changing Base or Discr; another recompute may be needed after generated nodes are created.

Use a connected edge sequence. FHPath can insert connecting segments across gaps between disconnected edges. For a closed loop, inspect the first and last generated nodes and use an explicit FHEquiv if they are distinct objects representing the same electrical junction. Generated nodes can change when the path is edited; recheck attached ports and connections afterward.

5. Define electrical connections and ports

Two segments are directly connected when they reference the same FHNode. Separate FHNodes at identical coordinates remain separate electrical nodes until equivalenced. Avoid relying on visible contact between segment shells.

  • FHEquiv: select at least two FHNodes and click FHEquiv to short them electrically. With more than two selected nodes, the command creates a chain of pairwise equivalences. These export as .equiv statements and do not add a conductor or a resistance.
  • FHPort: select two FHNodes and click FHPort. Inspect NodePos and NodeNeg; the first selected node becomes positive and the second negative. A port exports a .external statement defining a terminal pair for impedance extraction.
  • Check each port's node references and the intended current/return network. A port's displayed arrow is a terminal-polarity marker, not a computed current vector or an additional conductor.

Create a separate FHPort for every terminal pair whose impedance or coupling is required. A port alone does not define a conductor between its terminals. The native port exporter writes the node pair but does not currently include an explicit FastHenry port name from the object's Label.

6. Create uniform reference planes and holes

  1. Create a Draft Rectangle or Part Box for the rectangular plane's size and placement.
  2. Select it and click FHPlane. You may also select existing FHNodes and FHPlaneHoles to adopt when creating the plane.
  3. Set Thickness. For a Part Box Base, its Height controls and overrides Thickness; for a Draft Rectangle, set Thickness on FHPlane.
  4. Set seg1 and seg2, the numbers of grid segments along the plane's local length and width. Defaults are 10 and 10.
  5. Set optional segwid1 and segwid2 to make the branches narrower than their spacing, for a meshed plane. Zero selects the full-spacing widths. The workbench limits widths to the corresponding spacing.
  6. Set positive Sigma, nhinc and rh overrides if required. The plane's nhinc subdivides its thickness; it is distinct from seg1 and seg2.

FineMesh = false displays a coarse compound of two overlapping boxes. It does not show individual branches or holes. FineMesh = true builds the branch geometry, omitting branches incident on nodes removed by holes. The branch boxes remain geometry within one FHPlane object; they are not separate FHSegment objects. ShowNodes adds grid-node markers in the fine display. These display settings do not change the exported discretization.

Create FHPlaneHole objects with Type = Point, Rect or Circle. Set their reference coordinates and, as appropriate, Length/Width or Radius. Point removes a grid node; Rect specifies opposite corners through the reference point and its local Length/Width; Circle specifies a centre and radius. These holes remove discrete plane nodes and branches, rather than performing a continuous Boolean cut in the Base solid.

To add nodes or holes later, select the FHPlane and the unassigned FHNodes/FHPlaneHoles, then use FHPlaneAddRemoveNodeHole. The command toggles membership: selected nodes or holes already belonging to a plane are removed from it. Inspect the plane's Nodes and Holes lists after the operation.

Adopted node and hole coordinates are relative to the plane Placement and follow its movement; adoption projects their local Z coordinate to zero. Rectangular hole dimensions follow the plane axes. To connect a trace, adopt a node near the intended plane contact and share or equivalence that node with the trace endpoint. The export creates an internal plane-node reference and equivalences it to the ordinary FHNode. FastHenry resolves plane references to nearby discretization nodes, so inspect the grid around contacts and holes.

The native FHPlane tool supports uniform rectangular planes. For nonuniform planes defined by a binary discretization file or adaptive contacts, use a FastHenry input file and FHImport. FHImport can display those models without converting them into native FHPlanes.

7. Choose and inspect discretization

There are several independent controls:

ControlWhat it changes
FHPath DiscrThe straight-segment approximation of a curved centreline.
FHPlane seg1 / seg2The in-plane network of branches and contact locations in a uniform plane.
nhinc / nwinc and rh / rwThe parallel filaments through each segment cross-section and their size grading. For a plane, nhinc and rh control thickness subdivision.
Nonuniform file and contact statementsThe nonuniform in-plane partition and resulting segment widths and offsets, edited through the input files.

The ordinary segment and path displays show conductor envelopes, not individual cross-section filaments. Increasing nhinc or nwinc can therefore change the solver model without changing the visible envelope. A coarse plane preview also cannot verify holes or contact placement: enable FineMesh, or inspect the exported file with FHImport.

Choose a cross-section discretization sufficient for the highest frequency and the expected skin/proximity effects. Compare extracted quantities after refining the relevant controls. More curve chords do not replace cross-section filaments, and more thickness filaments do not refine the plane's in-plane contact geometry. The external solver can also refine segment lengths during its own run; FHImport displays the input geometry before that automatic refinement.

8. Export and run FastHenry

  1. Recompute and save the FreeCAD document. Check node connectivity, port polarity, cross-section orientation, plane membership and discretization.
  2. Check FHSolver.Units, Sigma, frequency settings and all per-object overrides.
  3. Set Folder and Filename. Prefer an existing writable destination. The exporter can create one missing directory, but does not recursively create parent directories.
  4. Click FHInputFile. Confirm overwriting if the destination file already exists.
  5. Read the Report view and inspect the generated text. The file contains the solver defaults, nodes, segments, path segments, uniform planes, equivalences, ports, frequency request and .end.
  6. Use Import FastHenry file to inspect the generated file, if desired. That visualization is a separate snapshot; later native edits require another export and reload.
  7. Run the input file using your external FastHenry installation, for example fasthenry model.inp where that command is installed, or the solver's own GUI.

FHInputFile exports supported native FH objects across the document, including hidden objects. It does not export arbitrary CAD solids or FHImport visualization compounds. It does not run FastHenry or perform a comprehensive electrical validation. A completion message should be checked against any preceding warnings.

FastHenry normally writes frequency-dependent complex impedance matrices to Zc.mat (with any requested output suffix). For nonzero frequency, resistance is the real part of Z and inductance is Im(Z)/(2πf). Preserve the port order and frequency labels when processing the matrices. The FH toolbar does not currently provide a solved-current-density importer; FHImport reads input geometry, not Zc or current-result files.

9. Import and edit FastHenry input files

Open the model and its source files

  1. Choose EM → Import FastHenry file, also available on the FastHenry toolbar.
  2. Select the root input file, normally .inp.
  3. Enable Also open all input files for text editing to open the input and every referenced plane-discretization file in separate syntax-highlighted tabs.
  4. Confirm the import. A progress dialog reports reading, plane discretization and surface construction; use Cancel to stop. Partially created geometry is removed on cancellation or failure.
  5. Inspect the grouped Part geometry in the tree and 3D view. Ordinary segments and individual ground planes are grouped inside an outer Part::Compound.

FastHenry has no recursive input-file hierarchy. A nonuniform plane can reference a separate binary cell-tree file using file=...; these dependencies are opened once each. Paths resolve relative to the input file's directory. file=NONE creates a nonuniform plane using contact-driven discretization and adds no external file.

Displayed geometry and supported input

The display follows FastHenry's unrefined PostScript geometry (-f simple with thick ground-plane segments, -g thick): four lateral faces per segment, with end faces omitted. Open-looking ends are therefore expected. All displayed coordinates are converted to physical FreeCAD millimetres using the file's .units statements.

The reader handles width-vector orientation, sequential defaults, unit conversion, uniform-plane holes, binary nonuniform discretization files, and the following contacts: initial_grid, initial_mesh_grid, point, line, rect, decay_rect, connection, equiv_rect and trace. Nonuniform segment widths and centre offsets follow the bundled FastHenry source implementation. Electrical constraints remain in the source; they do not add visible conductor geometry.

As in the solver, hole statements affect uniform planes; nonuniform mesh holes use initial_mesh_grid. Uniform-plane contacts are ignored by the solver and the reader. Nonuniform equivalence contacts affect electrical connectivity rather than the displayed surfaces. The Report view identifies ignored plane statements and malformed input.

FHImport does not run FastHenry, display solved currents, show individual cross-section filaments, or reproduce automatic longitudinal solver refinement. The imported objects are visualization geometry independent of the native FH solver primitives. Editing their FreeCAD properties does not update the source text, and FHInputFile does not convert them back into an input file.

Editor controls and reloading

ControlAction
Save / Ctrl+SSave the current physical source file. This does not rebuild the 3D model.
Save AllSave every open FastHenry source editor.
Save & ReloadSave the root input and its open related files, then replace the associated visualization as one undoable document operation. Newly referenced discretization files are opened after a successful reload.
Close AllClose all FastHenry editors, asking how to handle unsaved changes.
View → Wrap linesToggle line wrapping. The option is also available in the editor context menu and is remembered for subsequently opened editors.

If reloading fails or is cancelled, the previous model geometry and editor association are restored. The files have already been saved: restoring the document does not undo source-file writes. Correct the text and reload again. Closing the model's document prevents its editors from reloading until a new association is established by importing the input again.

Native input highlighting distinguishes directives, nodes/references, segments, planes, contact/hole keywords, comments and numbers. Plane-discretization files have their own tree-syntax highlighting.

Keep a valid title line at the start of a native input file and terminate its model with .end. Lines beginning with * are comments; a leading + continues the preceding statement. Entity names and keywords are case-insensitive. Refer to FastHenry_User_Guide.pdf and FastHenry_nonuniform_gndplane_manual.pdf, distributed with the solver, for the complete formats; the bundled solver source is the implementation reference for the importer.

10. Python examples

Use the FreeCAD Python console with a document open, or create one as below. This example creates one straight conductor and a port between its ends. It does not model a separate physical return conductor.

import FreeCAD as App
from freecad.EM import EM

doc = App.newDocument("FastHenryExample")
solver = EM.makeFHSolver()
solver.Units = "mm"
solver.Sigma = 5.8e4
solver.fmin = 1e4
solver.fmax = 1e8
solver.ndec = 1

start = EM.makeFHNode(X=0, Y=0, Z=0, name="Start")
end = EM.makeFHNode(X=10, Y=0, Z=0, name="End")
segment = EM.makeFHSegment(nodeStart=start, nodeEnd=end,
                           width=1, height=0.1, name="Trace")
port = EM.makeFHPort(nodePos=start, nodeNeg=end)
doc.recompute()

# Set an existing destination folder before exporting.
# solver.Folder = "/path/to/output"
# solver.Filename = "model.inp"
# EM.createFHInputFile(doc)

Set solver properties explicitly after creation when scripting. To add a path use EM.makeFHPath(baseobj); for a uniform plane use EM.makeFHPlane(baseobj, thickness=0.1, seg1=10, seg2=10) with a Draft Rectangle or Part Box. Recompute and inspect the result before exporting.

Import a file and open all its source editors in the GUI:

from freecad.EM import EM
model = EM.importFHInputFile("/path/to/model.inp", viewText=True)
files = EM.getFHInputFiles("/path/to/model.inp")
# To open editors separately for an existing import:

11. Troubleshooting checklist

  • Wrong physical size or resistance: check native FHSolver.Units and all Sigma values together. Native dimensions are numeric values in the selected unit; imported file geometry is converted to physical millimetres.
  • Segments look connected but the solver reports disconnection: inspect shared FHNode references and FHEquiv objects. Coordinate coincidence and surface contact do not short independent nodes.
  • Unexpected bridge in a path: check whether the Base contains disconnected edges that FHPath joined. Separate independent routes into different path objects.
  • Plane holes are invisible: enable FineMesh and verify that the holes belong to the plane. A hole can affect only the available discretization nodes; refine seg1/seg2 where necessary.
  • Plane nodes move unexpectedly: adopted nodes follow the plane Placement and have local Z projected to zero. Recheck the plane's Nodes list and the trace connections.
  • Changing filament counts does not change the display: segment envelopes do not show the parallel filaments. Inspect the exported nhinc/nwinc settings and check solver convergence.
  • Nonuniform plane unavailable in the native tool: define it in a FastHenry input file and inspect/edit it through FHImport.
  • Imported segments appear hollow: the PostScript-style display deliberately omits end faces. It is a surface visualization, not a collection of CAD solids.
  • Missing discretization file: check its file= reference and path relative to the input directory. file=NONE is a keyword, not a missing filename.
  • Text edits are not visible in 3D: saving alone does not rebuild the model. Use Save & Reload and inspect the Report view if the old geometry remains.
  • Failed reload restored the model but the file changed: source files are saved before rebuilding. Document rollback restores geometry, not the previous on-disk text.
  • Hidden or duplicate objects appear in an export: native FHInputFile exports supported objects throughout the document. Use separate documents for independent native models.
  • No solver results appear after export/import: run FastHenry separately. FHImport displays input geometry and does not import impedance matrices or current distributions.
